theorem is

```text
Hom(Circle, Circle) ~= Integers.
```

More precisely, construct an intrinsically groupoidal Circle HIT, an internal

```text
TypeEquiv(circle_base = circle_base, Integer_grpd)

TypeEquiv(

```

Then relate this groupoidal theorem to the existing directed result for the
walking endomorphism. The comparison must send nonnegative powers of the

Finally, close one representative ordinary type former—products—through a

## Architectural Verdict

The implementation must keep three notions separate.

### Intrinsic computational closure

HoTT clients work directly in `Grpd`. A selected former is computational when
its formation, constructors, eliminator, equality classifier, reflexivity
observations, transport, and safe beta laws are expressed by its intrinsic
groupoidal owners.

The current product already illustrates the intended architecture:

```text
Product_grpd(A,B) : Grpd

(p = q) in Product_grpd(A,B)
    --> ProductPathView(A,B,p,q).
```

Runtime rules belong here when they select an intended normal form and pass
the owner-position, subject-reduction, overlap, and warning audits.

### Categorical realization and preservation

`Path_cat : Grpd -> Cat` realizes equality as categorical arrows. Comparisons
such as

```text
Path_cat(Product_grpd A B)
    ~= Product_cat(Path_cat A)(Path_cat B)
```

are named coherence and interoperability results. The default deliverable is
an explicit comparison functor with homwise equivalence, preferably packaged
as `OmegaEquivAlong Cat_cat`. It is not a global runtime rewrite between the
two category heads: their current hom presentations are mathematically
equivalent but have different higher normal forms. A narrow `unif_rule` is
allowed only if a concrete typed consumer cannot elaborate through the named
bridge and the full proof-time audit is green.

### Groupoidification

Groupoidification freely inverts arrows. It is not `Core_cat`, which retains
only arrows that were already invertible. In ordinary adjunction notation the
direction is

```text
Groupoidify -| Inclusion -| Core.
```

With the current inclusion-like functor this would become

```text
Groupoidify_func : Cat_cat -> Grpd_cat
Groupoidify_func -| Path_cat_func.
```

The active adjunction interface can package this result only after the
functor, its higher action, unit, counit, and laws have been constructed. A
generic reflector is not a prerequisite for the bounded Circle goal. The
first result is instead the explicit WalkingEnd-to-Circle comparison and,
only if the concrete data stays tractable, its restricted universal property
for groupoidal targets.

## Circle HIT And Encode/Decode

The Circle is a genuine univalent groupoidal delooping:

```text
Circle_grpd : Grpd
circle_base : tau Circle_grpd
circle_loop : circle_base = circle_base

Circle_cat := Path_cat Circle_grpd.
```

The inverse loop is derived from equality symmetry; it is not installed as a
second unrelated generator. A strict one-object category with Unit objects
and Int homs is not an adequate univalent definition here: Unit object
equality is contractible while its proposed automorphism type is not.

The selected HIT signature also carries

```text
circle_is_groupoid : IsGroupoidGrpd Circle_grpd.
```

This is the groupoidal analogue of WalkingEnd's explicit one-dimensional
signature data. It is needed noncircularly because the trusted Integer is a
set-truncated telescope: defining `decode` by `integer_ind` requires its
path-valued target fibres to be sets. After encode/decode, the equivalence
with Integer supplies an independent sethood proof for the based loop space.
Thus the implementation both uses the selected dimensional HIT boundary and
checks that the computed loop classifier has exactly the expected dimension.

The proof follows the standard HoTT encode/decode architecture, expressed
through active emdash owners.

1. Convert `integer_succ_equiv` to a path
   `Integer_grpd = Integer_grpd` using groupoidal univalence.
2. Define by Circle recursion a family `CircleCode` with base fibre
   `Integer_grpd` and loop action `ua(integer_succ_equiv)`.
3. Define `circle_encode(p)` by transporting `integer_zero` in that family.
4. Define `circle_decode` by Circle and integer/telescope induction, using
   positive powers of `circle_loop` and powers of its inverse.
5. Prove the path-side inverse after generalizing the endpoint and applying
   ordinary path induction.
6. Prove the code-side inverse with Circle induction, integer induction, and
   sethood.

Expected user-facing observations include:

```text
encode(refl)             = 0
encode(circle_loop)      = succ(0)
encode(circle_loop^-1)   = pred(0).
```

The point beta rule should be judgmental where the active HIT policy permits.
The loop beta rule may remain a checked propositional equality rather than an
unsafe global rewrite. The final result should also prove that the loop space
is a set, so Circle is a 1-type in the active truncation vocabulary.

## Why This Is Not A WalkingEnd Instantiation

WalkingEnd classifies directed, noninvertible powers:

```text
loop^n <-> n : Nat.
```

Circle classifies equality loops and their inverses:

```text
loop^z <-> z : Integer.
```

The induction principles and normal forms are therefore different. The
Circle theorem is a distinct groupoidal proof, while reusing Nat arithmetic,
power utilities, `TypeEquiv`, univalence, and telescope localization. A
generic free-monoid/free-group encode/decode schema should be factored only
after the two concrete developments reveal a stable common interface.

Afterward construct

```text
walking_to_circle_func : Functor WalkingEnd_cat Circle_cat
```

by sending the walking base and generator to `circle_base` and
`circle_loop`. Prove that its action on the established Nat normal forms is
the nonnegative inclusion `Nat -> Integer`. This is strong concrete
group-completion evidence. Reserve the name “universal group completion” for
the later restricted or generic universal-property theorem.

## Product Transport And The Gray-Tensor Non-Goal

For `P : A x B -> Grpd`, `p : a = a'`, `q : b = b'`, and `u : P(a,b)`,
direct transport along the pair path has two sequential presentations:

```text
transport q (transport p u)   -- A, then B
transport p (transport q u)   -- B, then A.
```

Neither ordering is a second semantic transport. Both factor the same direct
transport, and path induction/interchange supplies their coherent equality.
For dependent Sigma the base-first order is canonical because the second
component is a `PathOver` above the first. The current constant-Sigma product
appropriately inherits that normalization order.

The product closure tranche should prove:

1. a named `Path_cat` product-preservation equivalence;
2. direct transport agrees with the base-first sequential factorization;
3. it agrees with the other coordinate order;
4. the resulting coherence diamond commutes; and
5. structured transport/induction agrees with primitive transport/`ind_eqr`.

These should initially be local lemmas and propositional equalities. No broad
rule should rewrite all product equality proofs to a canonical constructor.

The Gray tensor is a separate non-Cartesian monoidal product for genuinely
lax or pseudo two-dimensional structure. It may eventually deserve an
explicit `GrayTensor_cat`, but it does not replace ordinary Cartesian product
or resolve an ambiguity in ordinary product transport. `GCCI-GRAY` remains
deferred until such a higher-categorical consumer exists.
