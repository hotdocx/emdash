## Historical executive conclusion for the completed Circle tranche

The proposed circle theorem is the right next high-yield test of the
groupoidal layer, with one important architectural correction:

- `Hom(WalkingEnd, WalkingEnd) ≃ Nat` concerns a directed object whose
  generating arrow is not invertible;
- `Hom(Circle, Circle) ≃ Int` should concern a genuinely univalent groupoidal
  delooping whose generating arrow is an equality, hence automatically has an
  inverse; and
- passing from the first to the second is **groupoid completion**, not taking
  the core of a category. The core discards noninvertible arrows, whereas
  groupoid completion freely inverts them.

The current kernel already contains much more of the groupoidal
specialization than the overview sentence might suggest: `Path_cat`,
groupoidality, groupoidal products and dependent sums, path views, structured
transport, a structured version of `J`, and comparison with primitive `J` are
present. The real missing boundary is a systematic closure theorem for the
formers, together with a concrete groupoid-completion example. The circle and
its integer loop space provide exactly that example.

The ordinary product should remain the Cartesian/groupoidal product. Gray
tensor is not required to resolve the apparent ambiguity in transport along a
pair of paths. The two sequential transports are coherently equal by path
induction/interchange. A Gray tensor is a different higher-categorical
monoidal product, useful later for lax or pseudonatural two-dimensional
structure, not a replacement for ordinary products.

## Three notions that should not be conflated

### 1. Groupoidal embedding or specialization

`Path_cat : Grpd -> Cat` regards equality as categorical arrows. This embeds
the groupoidal layer in the categorical layer.

### 2. Intrinsic computational closure and categorical preservation

These are two related but different obligations.

The **intrinsic computational** obligation is owned inside `Grpd`: each
selected former has its own classifier, decoding, constructors, eliminator,
path classifier, reflexivity observations, and safe computation rules. For
products, that obligation is already substantially active through
`Product_grpd`, `ProductPathView`, and the runtime reduction of product
equality. HoTT clients use those operations directly and do not cast through a
categorical product.

The **categorical preservation** obligation compares that already-computing
groupoidal former with its categorical realization. A first important example
is a structured equivalence

```text
Path_cat(Product_grpd A B)
    ≃ Product_cat(Path_cat A)(Path_cat B).
```

The two category heads should not be identified by a global runtime rewrite.
On the left, product equality reduces through a constant-family `PathOver`;
on the right, categorical homs are a categorical product of component path
categories. The current `const_pathover` maps show these presentations are
equivalent, not that their complete higher normal forms are judgmentally
identical. The default bridge should therefore be a named functorial
equivalence. A narrow proof-time `unif_rule` is justified only if a real typed
consumer needs the two rigid presentations to elaborate as one and the rule
has passed the owner-position trust/overlap audit. A runtime fold is reserved
for a deliberately selected semantic normal form, not for a mathematical
equivalence.

The analogous matrix can later cover terminal objects, dependent sums,
dependent products where supported, and other selected formers. Such bridges
are important interoperability and coherence tests, but they are not what
makes the intrinsic HoTT operations computational.

### 3. Groupoid completion

A groupoid completion is a reflection that freely inverts arrows. For the
walking endomorphism, it sends the free monoid generated by one arrow to the
free group generated by one invertible arrow:

```text
Nat  --->  Int
  n  |-->  +n.
```

This cannot be implemented by `Core_cat`, which retains only arrows already
invertible. It requires a separate universal construction or, initially, a
specific comparison between WalkingEnd and Circle.

Adjunction direction matters. With an inclusion-like

```text
Path_cat_func : Grpd_cat -> Cat_cat,
```

generic groupoidification would be a functor

```text
Groupoidify_func : Cat_cat -> Grpd_cat
```

and an adjunction

```text
Groupoidify_func ⊣ Path_cat_func.
```

Thus groupoid completion is the **left** adjoint to inclusion. The maximal
core is the **right** adjoint: a functor from a groupoid into a category can
only use invertible arrows. The active emdash `Adjunction` machinery can
package the first statement after the functor, unit, counit, and higher action
have been constructed, but does not construct them automatically.

## Why a naïve one-object `BInt` is not the circle here

A strict category with `Unit` as its object type and `Int` as its hom type is
the ordinary one-object delooping of the group of integers. But it is not a
univalent category in the current emdash sense: all integer arrows are
isomorphisms, while the identity type of the sole `Unit` object is
contractible. Univalence would equate that contractible identity type with
the entire integer automorphism type, destroying the intended distinction.

The circle must therefore be presented as a genuine univalent delooping in
which the identity type of its base point carries the integers. The clean
construction is:

```text
Circle_grpd : Grpd
circle_base : τ Circle_grpd
circle_loop : circle_base = circle_base

Circle_cat := Path_cat Circle_grpd.
```

The inverse loop is then derived from equality symmetry/groupoidality rather
than installed as an unrelated second generating arrow. An explicit Rezk or
groupoid completion equivalent to this object is a possible later semantic
presentation, not the first implementation target.

## Recommended integer object

The strongest local candidate is the existing telescope localization of
successor:

```text
Int_grpd := TelescopeLocalization_grpd Nat_grpd nat_succ_function.
```

Use:

- `zero := inc(0,0)`;
- the existing forward transition as successor;
- the inverse of the forward equivalence as predecessor; and
- the existing set-truncation principle to control the easy encode/decode
  inverse and loop-space one-dimensionality.

This choice reuses current HIT infrastructure and makes “integers are the
localization/group completion of naturals at successor” executable. A signed
normal form may be proved later as an equivalence, but need not be the trusted
definition.

One caveat should be explicit: telescope localization initially gives a
localized set with an invertible shift. It should not be advertised as the
universal group completion of the additive monoid until addition and the
relevant universal property have actually been formalized.

## Circle encode/decode architecture

Follow the standard HoTT proof, specialized to the active emdash owners.

1. Convert the successor equivalence on `Int_grpd` to a path
   `Int_grpd = Int_grpd` using groupoidal univalence.

2. Define by circle recursion a code family

   ```text
   Code : Circle_grpd -> Grpd
   Code(circle_base) := Int_grpd
   ap Code circle_loop := ua(successor-equivalence).
   ```

3. Define

   ```text
   encode_x(p) := transport Code p zero.
   ```

4. Define `decode_x` by circle induction and integer/telescope induction,
   using positive powers of `circle_loop` and powers of its inverse.

5. Prove the hard inverse after generalizing the endpoint, then use ordinary
   path induction. This is precisely where the groupoidal proof is easier
   than the directed WalkingEnd proof: every path is generated under the
   equality eliminator, whereas directed arrows require a genuine directed
   induction principle.

6. Prove the other inverse by circle induction, integer induction, and
   sethood.

This is a new groupoidal proof, not a literal instantiation of the directed
WalkingEnd proof. The latter eliminates directed arrows and normalizes the
free monoid of nonnegative powers; the former eliminates equality paths and
must account for inverses and negative powers. They should nevertheless share
the existing Nat arithmetic/power utilities, use telescope localization for
the integer code, and be connected afterward by the comparison functor. A
generic “free monoid/free group encode-decode schema” should be factored only
after both concrete proofs reveal a genuinely common interface.

The headline outputs should be equivalences, not definitional rewrites:

```text
TypeEquiv(circle_base = circle_base, Int_grpd)

TypeEquiv(
  Hom Circle_cat circle_base circle_base,
  Int_grpd
).
```

The second follows transparently from the `Path_cat` hom computation. It is
also worth packaging the result through the existing `OmegaEquiv` interface.

Expected computation and usability results include:

- `encode(refl) = 0`;
- `encode(circle_loop) = succ(0)`;
- `encode(circle_loop^-1) = pred(0)`;
- once integer addition is available, composition/concatenation maps to
  addition;
- `circle_loop` is not the identity; and
- the loop space is a set, hence the circle is a 1-type and `Circle_cat` is a
  one-category in the appropriate current predicate.

The point computation rule should be judgmental where the active HIT policy
permits. As in the standard HoTT/Coq presentation, the loop computation rule
can be propositional rather than an unsafe global rewrite.

## Products, `J`, and the order of transport

At the foundational level there remains one equality eliminator. In the
active source its primitive right-based owner is `ind_eqr`; `ind_eq` is a
derived path-independent specialization, and the book writes the operation
as `J`. “Shape-reducible J” should not introduce a second equality axiom or a
parallel primitive. It can mean either a guarded former-specific runtime case
on the same `ind_eqr` head, or, when direct reduction would threaten subject
reduction or confluence, a named former-specific facade that delegates to
`ind_eqr`—as `nat_succ_ind_eqr` already does. Structured `PathOut` induction
is a categorical presentation for an already-functorial motive and is proved
to agree with `ind_eqr`; it is not a second primitive J.

Let `P : A x B -> Type`, let `p : a = a'`, `q : b = b'`, and let
`u : P(a,b)`. Transport along the pair path has two familiar sequential
presentations:

```text
-- first A, then B
transport (lambda b'. P(a',b')) q
  (transport (lambda a'. P(a',b)) p u)

-- first B, then A
transport (lambda a'. P(a',b')) p
  (transport (lambda b'. P(a,b')) q u).
```

Neither is the uniquely true semantic meaning. Both factor the same direct
transport, and path induction supplies their coherent equality. For a genuine
dependent sum, the base-first orientation is canonical because the second
path is a `PathOver` above the first; for a nondependent product, the current
constant-Sigma implementation inherits that sensible normalization order.

For a structured motive presented as a displayed category over
`Path_cat(Product_grpd A B)`, functorial action already provides the direct
transport. Composition provides sequential factorizations, and categorical
laws/interchange provide their coherence. Existing structured-transport and
structured-`J` comparison theorems then relate this action propositionally to
primitive equality transport and primitive `J`.

For an arbitrary raw motive, primitive `J` should remain the general rule and
compute at reflexivity. Merely inspecting the outer shape of the equality's
carrier does not determine arbitrary motive action. Thus “observational `J`
computes by the type and motive shape” should mean that registered structured
motives obtain more informative derived computation rules—not that every raw
motive receives a global syntactic decomposition rewrite.

The first product tranche should prove:

1. preservation of product by `Path_cat`;
2. equivalence between the direct pair transport and the base-first
   sequential transport;
3. equivalence/agreement with the other coordinate order;
4. the interchange/coherence diamond; and
5. agreement of these structured operations with primitive transport/`J`.

This should use local lemmas and propositional equalities. It should not
collapse proof provenance through broad global rewrites, nor install a global
rule that rewrites every product equality proof to a canonical constructor.

## Why Gray tensor is a separate direction

The Gray tensor is a non-Cartesian monoidal product of 2-categories. Its
generators contain the two coordinate directions and a specified
interchanger 2-cell; it is designed to model cubical functors and the
coherence of lax/pseudonatural higher transformations. That is relevant to an
eventual directed higher-categorical emdash layer.

It does not explain ordinary transport along a path in `A x B`: the identity
type already contains the required commuting square/coherence. Replacing
`Product_grpd` or `Product_cat` by Gray tensor would change the mathematical
object and break ordinary product semantics.

A later, explicitly named `GrayTensor_cat` may be valuable when emdash needs
native pseudo/lax two-dimensional transformations. It should enter through a
separate motivating consumer, not through the groupoidal product-closure
tranche.

### 1. The current strict naturality rules really are cut-elimination rules

The full ordinary naturality rules in `emdash3_2.lp` are square-shaped when
read extensionally, but they are not separately postulated component squares.
Their outer head is `comp_fapp0 Cat_cat`: categorical composition in
`Cat_cat`, hence composition of whole functors. For the post/left direction,
the active rule has the schematic form

```text
hom_postcomp_func(G,g) o tapp1_func(epsilon,X,Y)
    -->
tapp1_func(epsilon,X,Z) o hom_postcomp_func(id_A,g).
```

The pre/right rule analogously pushes a represented precomposition cut through
the whole `tapp1_func`. These are Došen-style cut-elimination rules because an
operational postcomposition or precomposition owner is accumulated and moved
through an off-diagonal action. They are not anti-SOP equations attached as
external naturality fields.

This observation changes the lax redesign. The strict rules should not be
replaced by arbitrary pointwise square records. A lax profile should expose a
higher arrow between the same two *whole composite functors*, with capped
pointwise cells obtained by projection. A selected strict constructor may then
collapse that higher arrow, and consequently its endpoints, to the current
cut-normal form.

### 2. The post/left laxity cell already has a correct projection source

Let

```text
epsilon : F => G
X       : Obj(A)

E_X := hom_(id_A,X)
D_X := hom_(G,F[X])
T_X := tapp1_at_transf(epsilon,X) : E_X => D_X.
```

The existing whole ordinary internal action is

```text
tapp1_int_fapp0_transf(epsilon)
  : hom_int(id_A) => hom_int(G) o Op_func(F),
```

and `T_X` is its first projection at the fixed source object `X`. Its component
at `Y` is the existing whole hom functor

```text
T_X[Y] = tapp1_func(epsilon,X,Y)
       : Hom_A(X,Y) -> Hom_B(F[X],G[Y]).
```

Now regard the Cat-valued transfor `T_X` through the already active displayed
internal-action ladder. For `g : Y -> Z` and `f : Hom_A(X,Y)`, the existing
cell

```text
fdapp1_int_cell(T_X,g,f)
```

has intrinsic endpoints

```text
D_X[g](T_X[Y](f))
    -->
T_X[Z](E_X[g](f)).
```

Under the ordinary hom computations this reads

```text
G[g] o epsilon[f]  ==>  epsilon[g o f].
```

Thus a capped ordinary post/left cell such as
`tapp1_post_cell(epsilon,g,f)` need not be a new naturality axiom. It can be a
transparent alias, or a stable runtime head linked by a projection rule, to

```text
fdapp1_int_cell(tapp1_at_transf(epsilon,X),g,f).
```

The stable-head option is justified only if it gives ordinary users and later

### 7. Strict and lax may coexist in the bounded prototype

The existing global strict cut rules do not themselves reduce the projected
laxity cells to identity arrows. Consequently a carefully documented
prototype can retain those rules while explicitly using the nonidentity cell
owners in new lax developments. This does not prove that the ambient
classifier is a completed generic lax map classifier, but it permits useful
experiments without rewriting the early kernel immediately.

Strictness can be selected per constructor. For example, if a particular
curried map `curry(H)[a]` is intended to be strict, narrow rules on that
constructor may reduce its compositor (and, where necessary for typing, its
two endpoint composites) to identity. Generic lax maps retain the projected
cell. Source comments and reports must track which theorems actually consume
the global strict rules.

The eventual clean architecture may classify map profiles explicitly, but
the prototype need not duplicate products, pullbacks, Sigma, Pi, represented
families, and every other construction immediately. Shared classifiers plus
projected coherence and constructor-specific strict computation are a
reasonable experimental boundary. A separate classifier becomes necessary
only when the system must prevent strict conversion from being available at
all, rather than merely refrain from using it.

### 8. Shared strict/lax classifiers do not construct `Groupoidify`

The shared-classifier prototype removes one important representational
blocker: the universal mapping property of groupoidification can quantify over
the ordinary map classifier while retaining explicit coherence cells, and a
strict specialization can collapse selected cells. It does **not** construct
the reflector.

A genuine generic operation still needs, at minimum:

```text
Groupoidify(C)             : Grpd
groupoidify_unit(C)        : C -> Path_cat(Groupoidify(C))
groupoidify_elim / transpose
groupoidify object, arrow, and higher-cell computation
unit/counit or beta/eta observations for the universal property.
```

The hard boundary is the free coherent inversion of every directed cell and
the iterable higher action. The completed WalkingEnd-to-Circle map is the
first concrete instance and evidence for the intended semantics; it is not a
generic reflector.

Once both generic groupoidification and actual homotopy truncation exist, a
truncated tower can be derived.  In the revised sorted presentation its
primary member is a code in the smaller classifier:

```text
Groupoidify_le_ntype(n,C)
  := Trunc_ntype(n,Groupoidify(C))
  : Obj(NType_cat(n)).

Groupoidify_le_carrier(n,C)
  := ElNType(n,Groupoidify_le_ntype(n,C))
  : Grpd.
```

No mutually primitive family of all `Groupoidify_n` operations is required.
The first line is the classified result and the second is only its decoded
carrier.  But truncation alone cannot groupoidify a category: its input is
already a groupoidal type. Conceptually, free inversion happens first and
Postnikov truncation second. For an already groupoidal input, the first step
is equivalent to the identity and the tower reduces to ordinary truncation.

This distinction also fixes the WalkingEnd example. Its groupoidification is
the Circle-like free groupoidal loop. The 1-truncation still has loop group
`Int`; the 0-truncation of the connected Circle is merely contractible as a
set and therefore cannot be what “freely invert the generator” means.

  --> StrictFunctorData(B,C)

On the intended generic-lax reading of the ambient classifier, the final Hom

For this to be a full-subcategory facade rather than a category with arbitrary

then controls computation without changing the mathematical object represented
by a strict functor.

The current global ordinary strict cuts remain an explicitly tracked

claim of faithful general lax semantics waits for those global cuts to be
migrated to profile-selected rules.

### 11. The exact Crans--Gray closed structure

For strict omega-categories, the Crans--Gray tensor is a non-symmetric
biclosed monoidal product. One must therefore retain the order of the two
factors and distinguish the two internal homs. In the notation of Ara and
Maltsiniotis, the defining natural bijections are

```text
StrOmegaCat(A tensor B, C)
  ~= StrOmegaCat(A, Hom_oplax(B,C))

StrOmegaCat(A tensor B, C)
  ~= StrOmegaCat(B, Hom_lax(A,C)).
```

Both internal homs have strict omega-functors as their objects. Their higher
cells are respectively oplax and lax transfors in all dimensions. Thus the
phrase “the inner `Functor(B,C)` has lax transformations” is directionally
right only after `Functor` has been replaced by the correct full internal-hom
omega-category and the lax/oplax orientation has been fixed.

The nLab formula which initially looked mysterious,

```text
[X,Y] = StrOmegaCat(X tensor G_bullet,Y),
```

is not an additional theorem competing with the curry/uncurry
characterization. The right side denotes a *globular object*: at dimension
`k` it is the set of strict omega-functors

```text
X tensor G_k -> Y,
```

where `G_k` is the standard `k`-globe. Ara--Maltsiniotis write the same
construction as

```text
Hom_lax(X,Y)_k = StrOmegaCat(X tensor D_k,Y),
```

while the other variance is

```text
Hom_oplax(X,Y)_k = StrOmegaCat(D_k tensor X,Y).
```

The globe formula is precisely what assembles the entire internal-hom
omega-category, including its higher transfors. Biclosedness then supplies
the curry/uncurry bijections above.

This is highly compatible with the emdash philosophy. Rather than hand-write
finite unitor/compositor/pentagon records, one can aim to characterize the
whole lax or oplax hom by an iterable globe/internal-action construction. The
ordinary source-internalized and target-internalized action ladders are small
local prototypes of the two variances, but they are not yet the completed
Crans--Gray internal homs.

### 12. Gray curry supplies introduction and elimination

Choose one orientation and expose the right closure computationally as

```text
gray_curry_R
  : StrictMap(GrayTensor(A,B),C)
      -> StrictMap(A,GrayHom_R(B,C))

gray_uncurry_R
  : StrictMap(A,GrayHom_R(B,C))
      -> StrictMap(GrayTensor(A,B),C).
```

Transposing the identity on `A tensor B` gives

```text
coeval_right(A,B)
  : A -> Hom_oplax(B, A tensor B).
```

From the left closure one likewise gets

```text
coeval_left(A,B)
  : B -> Hom_lax(A, A tensor B).
```

These are good “introduction” surfaces.  In particular, successive object,
arrow, and higher-action projections of `gray_curry_R(id)` construct tensor
objects, the two coordinate arrow families, and their interchanger.

Conversely, `gray_uncurry_R` is the elimination/map-out operation

```text
(A -> Hom_oplax(B,C))
    ->
(A tensor B -> C),
```

and the mirror operation for `Hom_lax`.  Evaluation is the special case

```text
gray_uncurry_R(id_(GrayHom_R(B,C)))
  : GrayTensor(GrayHom_R(B,C),B) -> C.
```

There is no separate operation
`strictness(gray_curry_R(H)[X])`.  The term

```text
gray_curry_R(H)[X] : Obj(GrayHom_R(B,C))
```

already contains the strict-functor package, and the profile inclusion
exposes its underlying functor.  Likewise the readable Gray interchanger is
initially an alias/projection of the selected laxity component:

```text
gray_interchanger(H,a,b)
  := laxity_component(
       underlying(gray_curry_R(H)[a]),
       b).
```

It is not an independent square axiom.  A stable head is justified only if it
reduces to this whole-action projection.

Thus the proposed concise presentation is mathematically sound **if** “unit
plus transpose” abbreviates a natural adjunction with beta/eta inverses and
iterable higher action.

The unit alone does not characterize the tensor. A computational emdash
presentation still needs selected owners for:

- tensor action in both variables;
- the right and left internal homs;
- evaluation/coevaluation and curry/uncurry;
- beta and eta computation or comparison;
- naturality/higher action of those operations; and
- the monoidal associator/unit boundary, if the result is to be advertised as
  the full Crans--Gray monoidal structure.

For an initial one-sided consumer, one closure and its beta/eta laws may be a
reasonable tranche. It should be called a right- or left-closed Gray slice,
not the completed biclosed tensor. “Eliminator” is a useful type-theoretic
analogy here, but this is a universal-property transpose rather than a HIT
dependent eliminator.

### 13. The current Cartesian curry scaffold already exists

The active kernel contains more Cartesian closure infrastructure than the
discussion initially assumed:

```text
curry_func_func
  : Functor_cat(Product_cat(A,B),C)
      ->
    Functor_cat(A,Functor_cat(B,C))

uncurry_func_func
  : Functor_cat(A,Functor_cat(B,C))
      ->
    Functor_cat(Product_cat(A,B),C).
```

They are formal semantic packages assembled from product pairing,
composition, and evaluation, with object-level projections
`curry_func`, `curry_fapp0_func`, and `uncurry_func`. The source explicitly
states that full product/curry adjunction coherence remains future work.

Therefore the corrected conclusion is:

- emdash has formal Cartesian curry and uncurry operations;
- it does not yet have the complete beta/eta equivalence or adjunction;
- those operations use the current `Functor_cat`, whose ordinary
  functoriality and naturality cuts are globally strict; and
- a Gray closure must not silently reinterpret this existing inner
  `Functor_cat` as a lax/oplax hom.

There is consequently no proved inconsistency. The current Cartesian
scaffold is a strict line whose final coherence is incomplete. A later
profile-aware redesign can preserve it as the strict specialization, with
constructor-specific rules asserting that curried Cartesian maps have
identity laxity witnesses. The Gray line then uses a separately named
`GrayHom_oplax`/`GrayHom_lax` (names provisional), even if both ultimately
share most of the generic map and internal-action infrastructure.

### 14. The decisive low-dimensional Gray test

Let `I` be the walking arrow. The Crans--Gray tensor `I tensor I` has four
objects, horizontal and vertical boundary arrows, and one directed
interchanger 2-cell between the two composites around the square. Reversing
the factor order or choosing the other internal hom reverses the relevant
lax/oplax orientation. This is the smallest test which distinguishes Gray
tensor from Cartesian product.

Under right currying, the identity

```text
id : I tensor I -> I tensor I
```

becomes

```text
coeval_right : I -> Hom_oplax(I, I tensor I).
```

The two outer objects are the two strict functors that include the inner
walking arrow at the left and right endpoints. The outer generating arrow is
a lax/oplax transfor between those functors. Its object components are the
horizontal boundary arrows; applying its whole internal action to the inner
generating arrow produces the interchanger cell.

In emdash projection language, this test should not stop after observing a
`tapp1_fapp0` off-diagonal 1-arrow. It should check that the whole projected
laxity owner, and then its `fdapp1_int_cell`-style component, has the two
boundary composites as endpoints and reduces to the named Gray interchanger.
The mirror closure should produce the opposite orientation. A next-action
test on a Gray cube should then expose the first nontrivial higher coherence.

Two useful semantic checks accompany the square:

- the `n=1` truncation/reflection of the Crans--Gray tensor is the Cartesian
  product of ordinary categories; and
- the `n=2` truncation is Gray's tensor product of strict 2-categories.

Hadzihasanovic's combinatorial presentation supplies a complementary model:
the underlying graded poset of `P tensor Q` is the product poset, while the
orientation includes a dimension-dependent sign; the tensor is
dimension-raising and generally non-symmetric. This is valuable validation
and a possible finite-shape implementation guide, but the foundational
emdash interface should be the biclosed/internal-action presentation rather
than a semantic detour through chain complexes.

### A. Scope correction: preserve the original laxity goal

### B. The fifth presentation: a groupoidal profile of the directed calculus

The promising idea is not to replace the globular/J identity theory by a new
simplicial semantics.  It is to present paths through the already-computing
directed interface wherever this preserves their intended groupoidal meaning:

```text
underlying groupoidal data and J
    -> Path_cat / path_lift categorical realization
    -> ordinary Catd, homd_, Sigma, and internal action
    -> lax witnesses in general
    -> pseudo witnesses automatically in groupoidal homs
```

For `A : Grpd`, the active realization is already

```text
PathReal(A) := Path_cat(A),
```

with the recursive computations

```text
Obj(PathReal(A))       = A,
Hom_PathReal(A)(x,y)  = PathReal(x = y),
id_x                  = refl_x.
```

Thus a path is exposed as an ordinary categorical arrow, while a path between
paths is exposed as the next hom arrow.  The underlying equality remains the
same groupoidal equality; the directed presentation supplies the operational
API consumed by `fapp*`, `tapp*`, `homd_`, represented actions, and their
higher projections.

Path composition likewise has two useful presentations:

```text
path_comp_cat(q,p) := comp_fapp0(Path_cat(A),q,p),
path_comp_J(p,q)   := eq_trans(p,q).
```

The active `path_comp_eq_trans` compares them propositionally.  The
categorical head should remain the owner inside the directed action calculus;
the transparent J term remains the ordinary HoTT presentation.  No global
rewrite from one whole presentation to the other is proposed here.

### D. `PathOver` and `homd_` are two orientations of dependent path data

### E. Why generic laxity becomes pseudo automatically

Suppose the generic internal action exposes a compositor

```text
phi_F(g,f) : F[g] o F[f] -> F[g o f].
```

Its interpretation depends only on the classifier in which it lands:

```text
arbitrary directed hom   -> a potentially noninvertible laxity cell;
Path-realized hom        -> an automatically invertible pseudo cell;
selected strict profile  -> a cell reduced to identity/reflexivity.
```

This is the central payoff of the groupoidal profile.  No duplicate
hand-written pseudofunctoriality hierarchy is required.  When the same generic
cell lands in a path category, it is a path and hence invertible.  Lax versus
oplax orientation remains visible, while path symmetry supplies the reversed
groupoidal orientation.

The current globally installed strict functoriality/naturality comparisons do
not invalidate this prototype reading as long as they are documented and no
rule collapses the extracted laxity cell itself to identity.  A later
profile-aware migration can move those strict endpoint comparisons to the
actual strict consumers.
