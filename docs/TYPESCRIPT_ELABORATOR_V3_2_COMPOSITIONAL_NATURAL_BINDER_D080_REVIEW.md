## Independent Review

The frozen proposal identifies a facade-level scope omission rather than a
missing mathematical construction. The active endpoint compiler already has
two sound branches: a finite direct displayed-functor chain and a scoped
`compileDisplayedContextual` compilation. The latter is already exercised by
finite grouped `:^nd` telescopes and owns its object and base-arrow behavior
through existing displayed constructions.

The proposed one-slot context is classifier-exact. Its source is the active
displayed source family, its sole wiring is that family's displayed identity,
and its active ordinals are exactly the hidden base and exposed fibre tokens.
Consequently `fibrePair(a,a)` compiles to the existing displayed diagonal; it
does not become an externally asserted pointwise function.

Installing the context around callback construction is necessary. Open
`identityCell` validates and compiles its endpoint immediately, before the
outer point factorer runs. Adding a later special case to the point factorer
would therefore be both ineffective and architecturally inferior. Reusing the
existing context stack lets the unchanged identity constructor recover the
same internally coherent displayed functor already accepted by 1F.

Contextual-profile gating preserves the historical base profile. The direct
bare-slot and finite-chain paths remain available everywhere they were before;
only profiles that already authorize `compileDisplayedContextual` can reach
fibre pairing, evaluation, or another reviewed contextual endpoint. Exact
source/target-functor checks in the shared point factorer remain the final
guard, so a body whose recovered endpoint differs from the declared displayed
transformation endpoints still fails closed.

Stack-owner checking in `finally` is required for both facades. It preserves
callback scope and makes nested or exceptional construction unable to leak an
endpoint context. No token, callback, equation, or proof object is retained.

Prerequisite propagation is semantically important. A fibre diagonal uses
product pairing that a direct chain does not need. The compact and expanded
abstraction evidence must therefore include both structural and dependent
requirements collected by the endpoint context, while historical direct
cases retain their existing empty additions and exact Core.

The chosen consumer is representative rather than ad hoc. Identity at a fibre
diagonal combines repeated variable use, displayed product structure, natural
introduction, and internal base-arrow/higher action. Exact compact, expanded,
and closed-owner equality is a strong rejection oracle. The already-existing
text grammar and resolver should inherit the behavior without code changes;
any need for a new parser branch would indicate that the proposed boundary was
misidentified.

No universal fixed/open compiler follows from this result. Ordinary and
displayed algebras remain separate classifier-indexed instances. The proposal
also correctly excludes new kernel/Core/checker/runtime owners, curry,
total-context encoding, casts, external naturality equations, browser, book,
and transfer changes.

## Decision

Approve exactly `DISPLAYED-NATURAL-ENDPOINT-CONTEXT-1G` as frozen at the
reviewed checkpoint. Activate the existing one-slot displayed endpoint context
only around the compact unary and expanded open-fibre natural callbacks in
contextual profiles; propagate its prerequisite sets; require exact diagonal
identity Core/type/action parity and inherited text behavior; and preserve all
recorded negative and base-profile boundaries. Do not add a special identity
case, universal operation table, new owner, parser route, or external
coherence payload.
